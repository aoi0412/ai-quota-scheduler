# デスクトップ Claude Code 向け 指示書（2026-10-22）

Mac 側セッションからの引継ぎ。読む人 = Linux デスクトップ上の Claude Code。

## 1. 背景

- 目的: Claude サブスク 5時間枠・週間枠の**余り**だけで harness2（google-research/harness2、自己改善エージェント枠組み）を回す。本人（ユーザー）利用 最優先。
- 本リポジトリ `ai-quota-scheduler` = 余り枠スケジューラ本体。設計書・計画 確定済、実装 未着手。
  - 設計書: `docs/superpowers/specs/2026-10-21-ai-quota-scheduler-design.md`
  - 本体計画（13タスク）: `docs/superpowers/plans/2026-10-21-ai-quota-scheduler-core.md`
- harness2 fork: `aoi0412/harness2`（main）。Mac 側で追加済:
  - コンテナ実行一式 `docker/`（Dockerfile, compose.yml, entrypoint.sh, README.md）
  - `harness2/preflight.py`: キー付き JobBench judge（AI Studio）で gcloud 確認 省略
- このデスクトップ = 常時稼働の本番機。最終的に ai-quota-scheduler 常駐先。

## 2. 現状・既知の問題

- Mac 検証: コンテナ build + `harness2-demo` 成功。JobBench setup は Mac ディスク不足で未完了 → 本機で実施。
- モデル: AI Studio 無料 Gemini API キー（`.env`）。無料枠 入力 **250k tokens/分** 上限 → JobBench 1 rollout でも 429 で失敗した実績あり。試走失敗しても想定内。
- `.env` はユーザーが Mac から手動コピー。**git に入れない・中身を表示しない・チャットに出さない**。
- Claude Code 実行役（substrate）は harness2 に未実装（別計画、未作成）。

## 3. 作業（順番どおり。各フェーズ終了で ユーザーに報告して停止）

### フェーズ1: harness2 コンテナ環境 構築・確認

1. 前提確認: `docker info`、`docker compose version`、`git`、ユーザーが docker グループ所属。足りなければ ユーザーに報告（sudo 系はユーザーに依頼）。
2. `ghq get aoi0412/harness2`（無ければ `~/ghq/github.com/aoi0412/harness2` に git clone）。
3. `.env` 存在確認（`test -f .env`）。無ければ ユーザーにコピー依頼して停止。`HARNESS2_JUDGE_API_KEY` 空かどうかだけ確認（値は表示しない）。
4. `docker/README.md` の手順で build（`--build-arg UID=$(id -u) --build-arg GID=$(id -g)`）。
5. `harness2-demo --output /tmp/demo --k 2` → 「2 tasks completed; 0 failed」確認。
6. `harness2-setup jb` → 「Installation complete.」確認。
7. `harness2-check --bench jb` → 「Ready: jb/oc; 65 tasks」確認。
8. 任意: 1タスク試走（`--only-domains statisticians --max-tasks 1 --k 1 --mode parallel`）。429 で失敗 → 原因として報告のみ（回避策の実装はしない）。

完了条件: 5〜7 成功。結果・ディスク残量・所要時間を報告。

### フェーズ2: ai-quota-scheduler 本体 実装

- フェーズ1完了後、ユーザー了承を得てから開始。
- 計画 `docs/superpowers/plans/2026-10-21-ai-quota-scheduler-core.md` を Task 1 から順に TDD で実装。各タスク: 失敗テスト → 実装 → テスト通過 → コミット。
- 計画と設計書が食い違う場合 → 設計書優先、ユーザーに報告。
- 計画外の判断 → コミットメッセージかタスク報告に明記。

## 4. ルール

- 言語 Python 3.12 + uv。`uv pip` でなく `uv add` / `uv sync`。
- コミット: Conventional Commits。末尾 `Co-Authored-By` 行は Claude Code 既定に従う。
- push: ユーザー了承後のみ。force push 禁止。
- 秘密情報（`.env`、API キー、`~/.claude` 認証情報）: 読取表示・コミット禁止。
- 破壊的操作（`rm -rf`、`docker system prune`、volume 削除）: 事前にユーザー確認。
- harness2 本体の改造（Claude Code substrate 等）は本指示書の範囲外。必要と判断したら提案のみ。
